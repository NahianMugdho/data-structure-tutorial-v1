Graph কী? কীভাবে কাজ করে?

Graph হলো “জিনিস” আর “জিনিসদের মধ্যকার সম্পর্ক”-এর ছবি। জিনিস = vertex / node (বিন্দু), সম্পর্ক = edge (রেখা)। Tree-র বিপরীতে graph-এ cycle (ঘুরে নিজের কাছে ফেরা পথ) থাকতে পারে। Tree হলো এমন graph যা connected ও cycle-হীন (n vertex ⇒ n−1 edge)।

সহজ উপমা: শহর = node, দুই শহরের রাস্তা = edge, রাস্তার দূরত্ব বা টোল = weight। ফেসবুকে প্রতিটি মানুষ = node, বন্ধুত্ব = edge।
Vertex / Nodeযে ব্যক্তি, জায়গা, কম্পিউটার বা বস্তুকে বোঝানো হচ্ছে। যেমন: শহর A, শহর B।
Edgeদুটি node-এর মধ্যকার সংযোগ। যেমন: A থেকে B যাওয়ার রাস্তা।
Weightকোনো edge-এর খরচ, দূরত্ব, সময় বা অন্য মান। যেমন: রাস্তার দূরত্ব ৫ কিমি।
Pathএক node থেকে অন্য node-এ যেতে ধারাবাহিকভাবে পার হওয়া edge-গুলোর পথ।

Graph-এর ধরন

ধরনসহজ ব্যাখ্যাউদাহরণ
Undirected Graphসংযোগের নির্দিষ্ট দিক নেই; A—B হলে দুই দিকেই যাওয়া যায়।দুই শহরের দ্বিমুখী রাস্তা
Directed GraphEdge-এর দিক নির্দিষ্ট; A → B মানে A থেকে B, কিন্তু B থেকে A নাও হতে পারে।একদিকের রাস্তা, Instagram follow
Weighted Graphপ্রতিটি edge-এর সঙ্গে একটি weight থাকে।দূরত্ব, ভাড়া বা সময়
Unweighted GraphEdge-এর আলাদা weight নেই; প্রতিটি edge-কে সমান ধরা হয়।বন্ধুত্বের নেটওয়ার্ক
Connected Graphপ্রতিটি node থেকে অন্য node-এ যাওয়ার অন্তত একটি পথ আছে।সব শহর কোনো না কোনোভাবে যুক্ত
Cycleকোনো node থেকে যাত্রা শুরু করে আবার সেই node-এ ফিরে আসা।A → B → C → A

কিছু গুরুত্বপূর্ণ শব্দ

  • Degree: একটি node-এর সঙ্গে কয়টি edge যুক্ত। Directed graph-এ In-degree (যত edge ঢোকে) ও Out-degree (যত edge বের হয়) আলাদা করে দেখা হয়।
  • Adjacent node: সরাসরি edge দিয়ে যুক্ত node-গুলো।
  • Subgraph: মূল graph-এর কিছু node ও edge নিয়ে তৈরি ছোট graph।
  • Tree: Connected এবং cycle-হীন graph। n টি node থাকলে tree-তে ঠিক n−1 টি edge থাকে।
Graph দিয়ে সমস্যা সমাধান — ৩ ধাপ:
  1. সমস্যাটাকে node (জিনিস) আর edge (সম্পর্ক) হিসেবে ভাবো।
  2. কম্পিউটারে রাখো: adjacency list বা adjacency matrix (নিচে দেখো)।
  3. প্রশ্ন অনুযায়ী algorithm চালাও — ঘুরে দেখা (BFS/DFS), ছোট পথ (Dijkstra…), কম খরচে জোড়া (MST)।
n vertex-এর complete undirected graph-এ edge = n(n−1)/2। ব্যবহার: সড়ক/নেটওয়ার্ক, সামাজিক সংযোগ, গেমের মানচিত্র, রাউটিং।

নিচের graph-এ A, B, C, D, E, F ছয়টি শহর কল্পনা করো। লাইনগুলো রাস্তা এবং লাইনের পাশের সংখ্যা রাস্তার দূরত্ব।

নিজে করে দেখো: নিচের যেকোনো node-এ ক্লিক করো — তার প্রতিবেশী ও degree দেখাবে।
🔍 আকার:

যেকোনো node-এ ক্লিক করো।

V এবং E কী? V = মোট vertex/node সংখ্যা, E = মোট edge সংখ্যা। Graph algorithm-এর Time Complexity-তে এই দুটি প্রতীক বারবার আসবে। এই উদাহরণে V = 6, E = 9।
Adjacency Listপ্রতিটি node-এর পাশে তার প্রতিবেশী node-গুলোর তালিকা রাখা হয়। Sparse graph-এ (edge তুলনামূলক কম) memory সাশ্রয়ী। Space: O(V+E)।
Adjacency MatrixV × V টেবিল বানানো হয়। i ও j node-এর মধ্যে edge থাকলে ঘরে 1 বা weight, না থাকলে 0/∞ রাখা হয়। Edge আছে কি না দ্রুত দেখা যায়। Space: O(V²)।

BFS — Breadth First Search

এক লাইনে: শুরুর node থেকে আগে কাছের সবাইকে, তারপর তাদের কাছের সবাইকে — ঢেউয়ের মতো ছড়িয়ে ঘুরে দেখা। ব্যবহার হয় Queue (লাইনে যে আগে দাঁড়ায় সে আগে বের হয় — FIFO)।

Traversal মানে graph-এর node-গুলোকে নিয়ম মেনে একে একে visit করা। একই node-এ বারবার চলে যাওয়ার ঝুঁকি থাকে, তাই কোন node আগে visit হয়েছে তা মনে রাখতে visited তালিকা/সেট রাখি।

সহজ উদাহরণ: তুমি A শহরে আছো। আগে A থেকে সরাসরি যেসব শহরে যাওয়া যায় সেগুলো দেখবে। তারপর ওই শহরগুলো থেকে এক রাস্তা দূরের শহরগুলো দেখবে। এভাবেই স্তর (level) ধরে এগোবে।
Queue কী? Queue হলো লাইনের মতো: যে আগে ঢোকে, সে আগে বের হয় (FIFO — First In, First Out)।
নিয়ম:
  1. শুরুর node-কে queue-তে রাখো এবং “দেখা হয়েছে” চিহ্ন দাও।
  2. queue-র সামনের node-টা বের করো — এটাই এখন visit করা node।
  3. তার সব প্রতিবেশীর মধ্যে যারা এখনো দেখা হয়নি, তাদের “দেখা হয়েছে” চিহ্ন দিয়ে queue-র পেছনে যোগ করো।
  4. queue ফাঁকা না হওয়া পর্যন্ত ২ ও ৩ বারবার করো।
কীভাবে চালাবে: “পরের ▶” চাপো। হলুদ node = দেখা হয়েছে, কমলা বর্ডার = এই ধাপের node, হলুদ edge = কোন node থেকে কে আবিষ্কৃত হলো। চাইলে “অটো” চাপো।
Data structureComplexityব্যবহার
QueueO(V+E)unweighted graph-এ এক vertex থেকে সব vertex-এর ছোট পথ (কম edge); বন্ধু-সুপারিশ; maze-এর সবচেয়ে ছোট পথ

DFS — Depth First Search

এক লাইনে: একটা পথ ধরে যতদূর যাওয়া যায় যাও; আর যাওয়ার জায়গা না থাকলে পেছনে ফিরে (backtrack) অন্য পথ ধরো। ব্যবহার হয় Stack (সবার ওপরে যেটা রাখা হয় সেটাই আগে বের হয় — LIFO) বা recursion।
Stack কী? Stack হলো প্লেটের স্তূপের মতো: যে সবার শেষে ঢোকে, সে আগে বের হয় (LIFO — Last In, First Out)। DFS recursion দিয়েও লেখা যায়।
নিয়ম:
  1. শুরুর node-কে stack-এ রাখো।
  2. stack-এর মাথা থেকে একটা node নাও। যদি আগেই দেখা হয়ে থাকে, বাদ দিয়ে পরেরটা নাও।
  3. না দেখা থাকলে visit করো এবং তার না-দেখা প্রতিবেশীদের stack-এ রাখো।
  4. stack ফাঁকা না হওয়া পর্যন্ত ২ ও ৩ বারবার করো। (stack-এ নিচে থাকা node-এ ফেরাটাই backtrack।)
BFS বনাম DFS: BFS “চওড়া” হয়ে ছড়ায় (queue), DFS “গভীরে” যায় (stack)। দুটোরই complexity O(V+E)। ব্যবহার: maze/puzzle-এর পথ, cycle খোঁজা, connected অংশ গোনা, গভীর ফোল্ডার খোঁজা।

Shortest Path — Dijkstra

এক লাইনে: এক উৎস (এখানে A) থেকে বাকি সব node-এ সবচেয়ে কম খরচের পথ। নেগেটিভ weight চলবে না। কৌশল greedy — এখনো চূড়ান্ত হয়নি এমন node-দের মধ্যে যার দূরত্ব সবচেয়ে ছোট, সেটাকেই চূড়ান্ত ধরো।
খুব গুরুত্বপূর্ণ: Dijkstra-তে negative weight থাকা যাবে না। কোনো edge-এর weight ঋণাত্মক হলে Bellman-Ford ব্যবহার করো।
মূল ধারণা: Greedy। প্রতিবার যেসব node-এর shortest distance এখনো চূড়ান্ত হয়নি, তাদের মধ্যে যার বর্তমান distance সবচেয়ে কম তাকে বেছে নিই, তারপর তার প্রতিবেশীদের distance আরও কমানো যায় কি না দেখি। এই আপডেটকে Relaxation বলে।
যদি dist[u] + weight(u, v) < dist[v] হয়, তাহলে dist[v] = dist[u] + weight(u, v)
নিয়ম:
  1. উৎসের দূরত্ব 0, বাকি সবার দূরত্ব ∞ ধরো।
  2. চূড়ান্ত হয়নি এমন node-দের মধ্যে সবচেয়ে ছোট দূরত্বের node u বাছো — u এখন চূড়ান্ত।
  3. u-র প্রতিটি প্রতিবেশী v-এর জন্য দেখো: d[u] + weight(u,v) < d[v] হলে d[v] কমিয়ে নতুন মান বসাও। একে বলে relax।
  4. সব node চূড়ান্ত না হওয়া পর্যন্ত ২ ও ৩ চলতে থাকবে।
কেন নেগেটিভ weight-এ ভুল? Dijkstra ধরে নেয় একবার চূড়ান্ত হলে আর কমবে না। নেগেটিভ edge পরে এসে সেটা কমিয়ে দিতে পারে।
কীভাবে চালাবে: “পরের ▶” চাপো। node-এর নিচের সংখ্যা = এখনকার দূরত্ব; হলুদ node = চূড়ান্ত; হলুদ edge = এ পর্যন্ত পাওয়া shortest-path tree।
Complexity: array দিয়ে O(V²); min-heap দিয়ে O((V+E) log V)। BFS দিয়েও unweighted graph-এ shortest path হয়, কিন্তু weighted-এ Dijkstra লাগে।

Bellman-Ford

এক লাইনে: Dijkstra-র মতোই এক উৎস থেকে shortest path, কিন্তু edge-এর weight নেগেটিভ হলেও কাজ করে। কৌশল: সব edge বারবার relax করো।
Negative weight কেন হয়? ধরো কোনো graph-এ পথের খরচ কমাতে ছাড়/ক্রেডিট দেওয়া হচ্ছে। কোনো edge-এ −3 মানে ওই edge পার হলে মোট খরচ ৩ কমে যায়। Dijkstra এখানে ভুল করতে পারে, তাই Bellman-Ford লাগে।
dist[v] = min(dist[v], dist[u] + weight(u, v))
Negative Cycle: কোনো cycle-এর edge weight-গুলোর যোগফল ঋণাত্মক হলে ওই cycle বারবার ঘুরে distance আরও কমানো সম্ভব। তাই নির্দিষ্ট shortest distance পাওয়া যায় না।
নিয়ম:
  1. উৎসের দূরত্ব 0, বাকি সব ∞।
  2. (V−1) বার এই কাজ করো: প্রতিটি edge (u→v, w)-এর জন্য দেখো d[u]+w < d[v] কি না; হলে d[v] আপডেট করো।
  3. আরও একবার (V-তম) সব edge দেখো। এবারও কিছু কমলে negative cycle আছে — তখন shortest path অর্থহীন।
কেন (V−1) বার? সবচেয়ে ছোট পথে সর্বোচ্চ V−1টা edge থাকে। প্রতি pass-এ অন্তত আরও এক edge দূরের সঠিক মান পাওয়া যায়। Complexity O(V·E)।
কীভাবে চালাবে: graph directed। উদাহরণ ১-এর edge: A→B = 4, A→C = 5, B→C = −3, C→D = 2; শুরু = A। একটি উদাহরণ বেছে “পরের ▶” চাপো — হলুদ edge = এখন যে edge দেখছি। (edge-এর ক্রম ইচ্ছাকৃতভাবে উল্টো রাখা, যাতে একাধিক pass কেন লাগে বোঝা যায়।)
Complexity: Time O(V × E), Space O(V)। Negative edge থাকলে ব্যবহারযোগ্য।

SPFA — Bellman-Ford-এর দ্রুত রূপ

এক লাইনে: Bellman-Ford সব edge বারবার দেখে — অনেক বাড়তি কাজ। SPFA (Shortest Path Faster Algorithm) শুধু যে node-এর দূরত্ব সদ্য বদলেছে, তার edge-গুলো দেখে। এজন্য queue লাগে।
নিয়ম:
  1. উৎসের দূরত্ব 0, বাকি ∞; উৎসকে queue-তে রাখো।
  2. queue-র সামনে থেকে u বের করো।
  3. u-র প্রতিটি edge (u→v, w) relax করো: d[u]+w < d[v] হলে d[v] কমাও, এবং v যদি queue-তে না থাকে তবে পেছনে যোগ করো।
  4. queue ফাঁকা হলে শেষ। (Negative cycle ধরতে প্রতিটি node কতবার enqueue/relax হলো তার count রাখতে হয়।)
সতর্কতা: SPFA সব ক্ষেত্রে Bellman-Ford-এর চেয়ে দ্রুত নয়। Average-এ অনেক সময় ভালো কাজ করলেও worst-case Time Complexity O(VE)। Negative edge থাকলে ব্যবহার করা যায়, কিন্তু negative cycle থাকলে finite shortest path নেই।

Floyd-Warshall — সব জোড়ার shortest path

এক লাইনে: Dijkstra ও Bellman-Ford একটি start node থেকে অন্য node-গুলোর shortest path বের করে। কিন্তু graph-এর প্রতিটি node থেকে প্রতিটি node-এ shortest distance জানতে চাইলে Floyd-Warshall — একে All-Pairs Shortest Path বলে। এটি Dynamic Programming ব্যবহার করে: প্রতিবার একটি node-কে মাঝের স্টেশন (intermediate vertex) ধরে দেখি, ওই node হয়ে গেলে কোনো দুই node-এর পথ ছোট হয় কি না।
dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
অর্থাৎ i থেকে j-তে সরাসরি যাওয়ার বর্তমান distance আর i → k → j হয়ে যাওয়ার distance তুলনা করো; যেটি ছোট সেটি রাখো।
নিয়ম:
  1. একটা V×V টেবিল d বানাও: সরাসরি edge থাকলে তার weight, নিজের থেকে নিজে 0, না থাকলে ∞।
  2. প্রতিটি node k-কে একে একে “মাঝের স্টেশন” ধরো।
  3. প্রতিটি জোড়া (i, j)-এর জন্য দেখো: d[i][j] = min(d[i][j], d[i][k] + d[k][j]) — i থেকে j-তে সরাসরি না গিয়ে k হয়ে গেলে কি কম হয়?
  4. সব k শেষ হলে টেবিলে সব জোড়ার উত্তর। Complexity O(V³)।
কীভাবে চালাবে: “পরের k ▶” চাপলে একটি করে node মাঝের স্টেশন হবে; কমে যাওয়া ঘর হলুদ। (উপরের graph, undirected)
Floyd-Warshall negative edge সামলাতে পারে, তবে negative cycle থাকলে shortest path নির্দিষ্ট হয় না। শেষে কোনো node-এর নিজের কাছে distance negative হলে (dist[i][i] < 0) negative cycle আছে।
Complexity: Time O(V³), Space O(V²)। ছোট/মাঝারি graph-এ সব জোড়ার shortest distance বের করতে সুবিধাজনক।

Minimum Spanning Tree (MST) ও Kruskal

সমস্যাটা কী? কয়েকটি শহরের মধ্যে এমনভাবে বিদ্যুৎ/ইন্টারনেটের তার বসাতে হবে যেন সব শহর সংযুক্ত থাকে, কিন্তু মোট তারের দৈর্ঘ্য বা খরচ যত কম সম্ভব হয়। এই সমস্যার সমাধানে MST ব্যবহার হয়।
Spanning tree: সব vertex যুক্ত অথচ cycle-হীন subgraph (V−1 edge)। MST: weighted graph-এ মোট weight সবচেয়ে কম spanning tree।
সহজ ভাষায়: কয়েকটা গ্রাম সবচেয়ে কম খরচে তার/পাইপ দিয়ে জুড়তে হবে, কিন্তু অকারণে ঘুরপথ (cycle) চাই না। নেটওয়ার্কে loop আটকাতে (spanning tree protocol)-ও লাগে।
MST আর Shortest Path এক জিনিস নয়। Shortest path-এ নির্দিষ্ট দুই node-এর মধ্যে পথের খরচ কমানো হয়; MST-তে সব node-কে যুক্ত করার মোট edge weight কমানো হয়।
Kruskal (greedy) — edge ধরে ধরে:
  1. সব edge weight অনুযায়ী ছোট → বড় সাজাও।
  2. একটা একটা করে edge নাও।
  3. edge-এর দুই প্রান্ত যদি আলাদা গ্রুপে থাকে (জুড়লে cycle হবে না) ⇒ নাও, গ্রুপ দুটো এক করো।
  4. দুই প্রান্ত যদি একই গ্রুপে থাকে (জুড়লে cycle হবে) ⇒ বাদ দাও।
  5. V−1টা edge নেওয়া হলে থামো। Complexity O(E log E)।
Cycle পরীক্ষা: সাধারণত Disjoint Set Union (DSU / Union-Find) দিয়ে দ্রুত বোঝা হয় দুই node আগে থেকেই একই component-এ আছে কি না — ডেমোর “গ্রুপ” ঠিক এটাই।
কীভাবে চালাবে: “পরের ▶” চাপো — সবুজ/হলুদ chip = নেওয়া হয়েছে, লাল কাটা chip = বাদ। নিচে প্রতি ধাপের গ্রুপও দেখা যাবে।

Prim — MST-এর অন্য পথ

এক লাইনে: Kruskal edge ধরে এগোয়; Prim একটা গাছ বড় করে — একটা node থেকে শুরু করে প্রতিবার গাছ থেকে বেরোনো সবচেয়ে সস্তা edge নেয়।
নিয়ম (Prim, greedy):
  1. যেকোনো একটি node (এখানে A) দিয়ে গাছ শুরু করো।
  2. গাছের ভেতরের node ও বাইরের node-কে জোড়া দেয় — এমন সব edge দেখো।
  3. তাদের মধ্যে সবচেয়ে কম weight-এর edge নাও; বাইরের node-টা গাছে ঢোকে।
  4. সব node গাছে ঢুকলে শেষ। Complexity O(V²) বা heap-এ O(E log V)।
Complexity: Kruskal: O(E log E) (edge sort-এর জন্য)। Prim: binary heap ও adjacency list-এ O(E log V); সাধারণ matrix/array পদ্ধতিতে O(V²)। সাধারণত connected, undirected, weighted graph-এ MST ব্যবহৃত হয়।
Kruskal বনাম Prim: দুটোরই MST-এর মোট weight একই হয়। Kruskal সাধারণত কম edge-এর (sparse) graph-এ সুবিধাজনক; Prim বেশি edge-এর (dense) graph-এ।
কীভাবে চালাবে: “পরের ▶” চাপলে নিচে বেরোনো সব edge-এর তালিকা আসবে; সবচেয়ে ছোটটি হলুদ chip।
