Tree কী?

Tree একটি non-linear data structure যেখানে data hierarchical (উপর-নিচ ধাপে) সাজানো থাকে। ফোল্ডারের ভেতরে ফোল্ডার, পরিবারের বংশতালিকা — সবই tree। এটি recursive সংজ্ঞা: প্রতিটি child নিজেই একটি ছোট tree (subtree)।

Tree-র সংজ্ঞা (তিনভাবে): (১) Node ও edge দিয়ে গঠিত hierarchical structure। (২) Cycle ছাড়া connected graph। (৩) যে graph-এ যেকোনো দুই vertex-এর মধ্যে ঠিক একটি পথ আছে।

✘ Tree নয় — E-F যুক্ত হওয়ায় C,E,F cycle তৈরি করেছে।

✔ Tree — কোনো cycle নেই।

গুরুত্বপূর্ণ বৈশিষ্ট্য: প্রতি জোড়া vertex-এর মধ্যে একটাই পথ · n vertex হলে ঠিক n−1 edge · Graph tree ⇔ minimally connected · n vertex ও n−1 edge-এর যেকোনো connected graph একটি tree · cycle থাকবে না · root থেকে যেকোনো node-এ একটাই পথ।

Tree-র পরিভাষা (ইন্টারেক্টিভ)

নিচের tree-টি PDF-এর উদাহরণ। একটি পরিভাষার বোতাম চাপলে সংজ্ঞা আসবে এবং সংশ্লিষ্ট node হলুদ হবে।

একটি বোতাম বেছে নাও।

Tree-র ধরন

General tree: child সংখ্যার কোনো সীমা নেই (ফোল্ডার, পরিবার)। Binary tree: প্রতি node-এ সর্বোচ্চ ২ child (left, right)। Binary tree-র বিশেষ রূপ:

Full/Strict (প্রতি node-এ 0 বা 2 child)
Perfect (সব internal node-এ 2 child, সব leaf একই level)
Complete/Almost complete (শেষ level বাদে পূর্ণ, শেষটি বাম থেকে)
Skewed (সবাই একদিকে, linked list-এর মতো, depth n−1)
Balanced: যেকোনো node-এ বাম ও ডান subtree-র height-এর পার্থক্য ≤ 1। Rooted binary tree: একটি root আছে এবং প্রতি node-এ ≤ 2 child। Labeled/Unlabeled: node-এ নাম থাকলে labeled।
সূত্র: n node-এর tree-তে n−1 edge · Height h-এ সর্বোচ্চ node = 2h+1−1 · Level k-এ সর্বোচ্চ 2k node · N level-এ সর্বোচ্চ 2N−1 · degree-2 node n₂ হলে leaf N₀ = n₂+1 · n leaf-এর full binary tree-এ মোট 2n−1 node · n unlabeled node-এ binary tree = 2nCn/(n+1) (n=3 ⇒ 5; labeled ⇒ 5×3! = 30; n=4 ⇒ 14)।

Binary Search Tree (BST)

BST হলো এমন binary tree যেখানে প্রতি node-এর বাম subtree-র সব মান তার চেয়ে ছোট, আর ডান subtree-র সব মান বড়। তাই খোঁজার সময় প্রতি ধাপে অর্ধেক বাদ পড়ে — গড়ে O(log n); tree একদিকে ঝুঁকে গেলে (skewed) O(n)।

উদাহরণ ১: 50,30,70,20,40,60,80
উদাহরণ ২ (ক্রমানুসারে insert): 50,70,60,20,90,10,40,100
Construct করার নিয়ম: প্রথম মান root; এরপর প্রতিটি মান root থেকে তুলনা করে নামতে নামতে ফাঁকা জায়গায় বসাও। উদাহরণ ২-এর inorder: 10,20,40,50,60,70,90,100 (সবসময় sorted)।
Search 40: 50-এ ছোট ⇒ বামে; 30-এ বড় ⇒ ডানে; 40 পেলাম। Insert 25: 50→বামে, 30→বামে, 20-এ বড় ⇒ 20-এর ডান child।
Delete-এর ৩ case: (১) Leaf — সরাও। (২) এক child — সেই child দিয়ে প্রতিস্থাপন। (৩) দুই child — ডান subtree-র সবচেয়ে ছোট (inorder successor) দিয়ে প্রতিস্থাপন করে সেটি delete। উদাহরণ: 30 মুছলে 40 ওর জায়গায় বসে।

BST ইন্টারেক্টিভ

কীভাবে চালাবে: সংখ্যা লিখে Insert দাও — tree নিজে সাজাবে। Search চাপলে খোঁজার পথ হলুদ হবে। Delete-এ তিন case-ই চলে। Preorder/Inorder/Postorder/Level চাপলে node-গুলো ক্রমানুসারে হলুদ হবে এবং ক্রম নিচে লেখা হবে।

Tree Traversal — প্রতিটি node ঠিক একবার ভিজিট

কোনো operation করতে আগে node-এ পৌঁছাতে হয়। ভিজিট করার ক্রম অনুযায়ী চারটি পদ্ধতি; প্রথম তিনটি Depth First, শেষটি Breadth First (queue ব্যবহার করে)।

Level order: root queue-তে রাখো → queue থেকে একটি node তুলে ভিজিট করো, তার child-দের queue-তে দাও → queue খালি না হওয়া পর্যন্ত।
ব্যবহার: BST-এর inorder = sorted output · Preorder থেকে expression-এর prefix, Postorder থেকে postfix · Postorder: tree মুছে ফেলতে · Level order: স্তরভিত্তিক কাজ · দুই traversal (inorder + preorder/postorder) থেকে tree পুনর্গঠন সম্ভব। উদাহরণ: Postorder = D B E C A, Inorder = D B A E C ⇒ root A (postorder-এর শেষ), বাম = {D,B}, ডান = {E,C} ⇒ Preorder = A B D E C।

Expression Tree

Operator হলো internal node, operand হলো leaf। Tree-র inorder দিলে infix, preorder দিলে prefix, postorder দিলে postfix expression পাওয়া যায়।

(a+b)/(a*b−c)+d
(5+3)*2
Infix: (a+b)/(a*b−c)+d · Prefix: + / + a b − * a b c d · Postfix: a b + a b * c − / d +। (5+3)*2: আগে 5+3=8, তারপর 8×2 = 16।

Heap (Min Heap ও Max Heap)

Heap একটি complete binary tree (শেষ level বাদে পূর্ণ, শেষটি বাম থেকে ভরা) যা priority queue ও heap sort-এ ব্যবহৃত হয়। Min heap: প্রতি parent ≤ তার child, তাই root = সবচেয়ে ছোট। Max heap: প্রতি parent ≥ child, root = সবচেয়ে বড়।

C code — সব একসাথে (কপি করার জন্য)

নিচে প্রতিটি function আলাদা সেকশনে ব্যাখ্যা ও অ্যানিমেশনসহ আছে। এখানে সবগুলো একসাথে — “ফুল কোড কপি” চাপলেই সব function ক্লিপবোর্ডে যাবে। কম্পাইল করে চালাতে চাইলে “header+struct সহ কপি” নাও।

সব function-এর মিল: প্রতিটিই recursion — আগে base case (node NULL), তারপর বাম ও ডান subtree-র জন্য নিজেকে call। প্রতিটি অ্যানিমেশনে বাম পাশে কোডের যে লাইন চলছে তা হলুদ হবে, আর ডান পাশে tree ও call stack দেখা যাবে।

১) Traversal — inorder, preorder, postorder

তিনটি function একই কাঠামোর; শুধু printf লাইনটি কোথায় বসেছে তা-ই পার্থক্য। “অংশ” মেনু থেকে পদ্ধতি বেছে ▶ চালাও। ধাপে ধাপে দেখতে পরে ▶ চাপো বা স্লাইডার টানো; নিজের tree-র মান লিখে Build দাও।

ব্যাখ্যা: if(r) মানে node NULL না হলে তবেই কাজ — NULL হলে কিছু না করে ফিরে যাওয়াই base case। Inorder: বাম → print → ডান। Preorder: print → বাম → ডান। Postorder: বাম → ডান → print। অর্থাৎ node কখন “ভিজিট” (print) হবে তা নির্ভর করে print লাইনের অবস্থানের ওপর।
মনে রাখো: BST-এ inorder সবসময় ছোট থেকে বড় (sorted)। Preorder-এর প্রথম মান root; postorder-এর শেষ মান root। সময় O(n); recursion stack লাগে O(h)।

২) BST Search

প্রতি ধাপে একটি node-এর সাথে তুলনা করে বাম বা ডানে যাই — বাকি অর্ধেক বাদ। key বদলে (যেমন 40, 65, 99) চালিয়ে দেখো: পাওয়া গেলে node সবুজ হয়, না পেলে লাল ডটেড NULL-এ গিয়ে থামে।

ব্যাখ্যা: (১) n==NULL হলে key নেই ⇒ NULL ফেরত; n->key==key হলে পেয়ে গেছি ⇒ সেই node-ই ফেরত। (২) নইলে key < n->key হলে বামে, না হলে ডানে — ?: (ternary) দিয়ে এক লাইনে। (৩) যা ফেরত আসে তা-ই সরাসরি উপরে পাঠানো হয়, তাই উত্তর stack বেয়ে উঠে আসে।
জটিলতা: O(h)। balanced হলে h ≈ log n; skewed হলে h = n ⇒ O(n)। পরীক্ষা: “কতবার তুলনা লাগবে” প্রশ্নে root থেকে ওই node পর্যন্ত পথের node সংখ্যাই উত্তর।

৩) BST Insert

নতুন key সবসময় একটি leaf হিসেবে বসে। নামতে নামতে NULL ফাঁকা জায়গা পাওয়া পর্যন্ত যাই, তারপর newNode বানিয়ে উপরে ফেরত পাঠাই। শেষে নতুন node হলুদ হয়ে tree-তে যুক্ত হবে।

ব্যাখ্যা: n->left = insert(n->left,key) — কৌশলটি হলো: recursive call যে pointer ফেরত দেয় সেটিই বাম child হিসেবে বসে। বেশিরভাগ সময় ফেরত আসা pointer আগেরটাই থাকে; শুধু NULL-এর জায়গায় call পৌঁছালে নতুন node আসে ও parent-এর সাথে জুড়ে যায়। শেষের return n মানে প্রতিটি node নিজের pointer ঠিকমতো ফেরত দেয়।
লক্ষ্য করো: এই কোডে সমান key (duplicate) else-তে পড়ে বলে ডানে যায়। insert-এর ক্রম বদলালে tree-র আকার বদলায় (10,20,30,40 ক্রমানুসারে দিলে skewed)। জটিলতা O(h)।

৪) Leaf গোনা ও Node গোনা

দুটোই “বাম subtree-র উত্তর + ডান subtree-র উত্তর” ধরনের। মেনু থেকে getLeafCount বা countnodes বেছে চালাও — প্রতিটি node-এর পাশে নীল রঙে তার subtree-র ফল ফুটে উঠবে।

getLeafCount: NULL ⇒ 0; বাম ও ডান দুটোই NULL হলে সেটি leaf ⇒ 1; নইলে বাম ও ডানের leaf সংখ্যা যোগ। countnodes: NULL ⇒ 0; নইলে 1 (নিজে) + বাম + ডান। r ? A : B মানে r NULL না হলে A, নইলে B।
যাচাই: binary tree-তে leaf = (degree-2 node সংখ্যা) + 1। দুটোই O(n) — উত্তর নিচ থেকে উপরে ফেরে, তাই এগুলো postorder-এর ধরন।

৫) Tree-র সর্বোচ্চ গভীরতা (maxDepth)

প্রতিটি node জানতে চায় তার বাম ও ডান subtree কতটা গভীর, তারপর বড়টির সাথে নিজেকে যোগ (+1)। নীল সংখ্যা = ওই node-কে root ধরলে subtree-র গভীরতা।

ব্যাখ্যা: NULL-এর গভীরতা 0। l ও r হলো দুই subtree-র গভীরতা; (l>r ? l : r) + 1 মানে বড়টি নিয়ে নিজের জন্য ১ যোগ। root-এর মানই পুরো tree-র maxDepth।
সতর্কতা: এই function node গোনে (শুধু root হলে ফল 1)। আগের পাতার “height” edge গোনে (শুধু root হলে 0)। তাই height = maxDepth − 1।

৬) isBST — tree কি আদৌ BST?

শুধু “বাম child ছোট, ডান child বড়” দেখলেই হয় না — পুরো subtree-র সব মান একটি সীমার ভেতরে থাকতে হয়। প্রতি node-এর পাশে তার সীমা [lo, hi] দেখা যাবে। “ভুল tree বানাও” চাপলে একটি মান এমনভাবে বদলানো হবে যাতে শুধু parent-এর সাথে মিললেও আসলে BST ভাঙে।

ব্যাখ্যা: শুরুতে সীমা (−∞, +∞)। বামে নামলে উপরের সীমা (hi) হয় parent-এর মান; ডানে নামলে নিচের সীমা (lo) হয় parent-এর মান। মান সীমার বাইরে গেলেই false। দুই subtree-ই true হলে তবেই true (&& বলে বাম false হলে ডানে আর যায় না)।
সীমা কেন দরকার: শুধু child-parent তুলনা করলে এমন tree ধরা পড়ে না যেখানে বাম subtree-র গভীরে root-এর চেয়ে বড় মান লুকিয়ে আছে। বিকল্প: inorder চালিয়ে দেখা মান বাড়ছে কিনা। জটিলতা O(n)।

৭) kthSmallest — k-তম ছোট মান

BST-এর inorder ছোট থেকে বড় ক্রমে চলে, তাই inorder-এ k-তম node-ই k-তম ছোট মান। কাউন্টার i বাড়াতে বাড়াতে i == k হলে থামি। নিচে i ও k দেখা যাবে; node-এর পাশের #১, #২… হলো ভিজিটের ক্রম।

ব্যাখ্যা: বাম subtree আগে খুঁজি। সেখানে উত্তর মিললে (L != INT_MAX) সরাসরি ফেরত। না মিললে বর্তমান node গুনি: ++*i। i == k হলে এই node-এর মানই উত্তর; নইলে ডানে যাই। INT_MAX মানে “এখনও পাইনি”।
খেয়াল রাখো: i একটি pointer (int *i), তাই সব recursive call একই কাউন্টার ভাগ করে — শুরুতে int i = 0; দিয়ে &i পাঠাতে হয়। k, node সংখ্যার চেয়ে বড় হলে INT_MAX ফেরে। জটিলতা O(h + k)।

সমস্যা ১: 50,15,62,5,20,58,91,3,8,37,60,24 insert করলে root-এর বাম ও ডান subtree-তে node কত?
বামে (<50): 15,5,20,3,8,37,24 = 7; ডানে (>50): 62,58,91,60 = 4 ⇒ উত্তর (7, 4)।
সমস্যা ২: 4টি distinct key দিয়ে কতটি BST? Catalan C₄ = 8C4/5 = 14।
সমস্যা ৩: 7,5,1,8,3,6,0,9,4,2 insert। Inorder = 0,1,2,…,9 (sorted)। Preorder = 7,5,1,0,3,2,4,6,8,9।
