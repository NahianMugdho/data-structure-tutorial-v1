Hashing — বাংলায় ধারণা

অনেক data-র মধ্যে একটা খুঁজতে হলে সাধারণত তুলনা করতে হয়। Hashing-এ একটি hash function key-কে সরাসরি একটি ছোট সংখ্যা (index) বানিয়ে দেয়, আর data সেই index-এর bucket-এ রাখা হয়। ফলে খোঁজার সময় n-এর ওপর নির্ভর করে না — গড়ে O(1)।

মূল কথা: key → hash function → index → hash table (একটি array)। এতে search, insert, delete — তিনটিই গড়ে O(1) সময়ে হয়। Hashing দিয়ে মূলত Set (শুধু key) ও Dictionary / Map (key–value জোড়া) বানানো হয়।
পরিভাষা: Key (যা দিয়ে খুঁজি) · Hash function h(k) · Hash value / index · Hash table (আকার m) · Bucket / Slot (table-এর এক ঘর) · Load factor α = n / m (n = key সংখ্যা, m = ঘর সংখ্যা)
হ্যাশ ফাংশন (Hash Function) হলো একটি নির্দিষ্ট গাণিতিক নিয়ম বা সূত্র, যা আপনার দেওয়া Key (যেমন কোনো আইডি, সংখ্যা বা শব্দ)-কে ইনপুট হিসেবে নিয়ে একটি ইনডেক্স (Index) বা ঘরের নম্বর বের করে দেয়। হ্যাশ টেবিলের সেই ইনডেক্স নম্বরটিই হলো ডেটা রাখার বা খুঁজে পাওয়ার ঠিকানা।
ঠিকানা বের করার মূল ধাপগুলো
  1. ইনপুট হিসেবে Key নেওয়া: ধরুন আপনার কাছে একটি আইডি বা নাম আছে, যেমন 105 অথবা "cat"।
  2. গাণিতিক সূত্র প্রয়োগ করা: হ্যাশ ফাংশন এই Key-এর ওপর একটি হিসাব চালায়—যেমন ভাগশেষ বের করা (modulo), অক্ষরগুলোর ASCII মান যোগ করা, বা বিট-লেভেল অপারেশন।
  3. টেবিলের সাইজের ভেতরে সীমাবদ্ধ রাখা: হিসাবের ফল যেন হ্যাশ টেবিলের মোট ঘরের সীমা ছাড়িয়ে না যায়, সেজন্য সাধারণত টেবিলের আকার (table_size) দিয়ে ভাগশেষ নেওয়া হয়।
  4. ইনডেক্স (ঠিকানা) পাওয়া: যে সংখ্যাটি উত্তর হিসেবে আসে, সেটিই হলো টেবিলের সেই নির্দিষ্ট ঘর যেখানে ডেটাটি রাখা হবে বা পরবর্তীতে খোঁজা হবে।
দুটি সহজ উদাহরণ
  • সংখ্যার ক্ষেত্রে (key % table_size): ধরুন আপনার হ্যাশ টেবিলে 10টি ঘর আছে (0 থেকে 9 পর্যন্ত ইনডেক্স) এবং আপনার Key হলো 43। হিসাবটি হবে: 43 % 10 = 3। অর্থাৎ ডেটাটির ঠিকানা হলো ইনডেক্স 3।
  • শব্দের ক্ষেত্রে (ASCII বা ক্যারেক্টার মানের হিসাব): কম্পিউটার প্রতিটি অক্ষরকে একটি সংখ্যায় চেনে (যেমন ASCII বা Unicode)। ধরা যাক, কোনো ফাংশন শব্দের অক্ষরগুলোর মান যোগ করে টেবিলের সাইজ 10 দিয়ে ভাগশেষ নেয়। 'A'-এর ASCII মান 65 এবং 'B'-এর 66 হলে যোগফল 131, আর 131 % 10 = 1—তাহলে ঠিকানা হবে ইনডেক্স 1।

অ্যানিমেশন: H(x) = x mod 10। প্রতিটি key-এর হিসাব হয়, তারপর সেটি নিজের index-এ গিয়ে বসে (▶ চাপো)।

সতর্কতা: O(1) হলো গড় (average) সময়। সব key একই bucket-এ পড়লে worst case O(n) হয়ে যায়।

Hash function ও Hash table

Hash function: Division (key mod m), Mid-square (key² এর মাঝের অংশ), Folding (key ভেঙে যোগ)। ভালো function দ্রুত হয়, collision কম করে, key সমানভাবে ছড়ায়।

Mid-squarek² বের করে মাঝের অংক নাওk = 25 → 625 → মাঝের অংক 2 (table size 10)
Foldingkey-কে ভাগ করে যোগ করো, তারপর mod123456789 → 123 + 456 + 789 = 1368 → শেষ ৩ অংক 368
ভালো hash function-এর বৈশিষ্ট্য: (১) Deterministic — একই key সবসময় একই index দেয়। (২) দ্রুত হিসাব হয়। (৩) key গুলো table-এ সমানভাবে ছড়ায় (uniform distribution)। (৪) collision কম হয়।
Division পদ্ধতিতে m কেমন হবে? সাধারণত m মৌলিক সংখ্যা (prime) নেওয়া ভালো। m = 10 আর key-গুলো 10, 20, 30… হলে সবাই bucket 0-তে পড়ে (সমস্যা ৮ দেখো)।
Load factor ও Rehashing: α = n/m। α একটি সীমা (যেমন 0.7 বা 0.75) পার হলে table প্রায় দ্বিগুণ বড় করা হয় এবং সব key নতুন m দিয়ে আবার hash করা হয় — একে rehashing বলে। একটি insert কখনো O(n) হতে পারে, কিন্তু গড়ে (amortized) insert O(1)।

Collision — কেন হয়, কী করতে হয়

Key-র সংখ্যা table-এর ঘরের চেয়ে বেশি হলে (pigeonhole principle) বা hash function ভালোভাবে না ছড়ালে দুই বা বেশি key একই index পায় — একে Collision বলে। নিচে hash(x) = x mod 5 নিয়ে 10 ও 15 দুটোই index 0 পায় (▶ চাপো):

Collision সামলানোর দুটি প্রধান পদ্ধতি: ১) Separate Chaining (table-এর বাইরে chain) এবং ২) Open Addressing (table-এর ভেতরেই খালি ঘর খোঁজা — Linear, Quadratic, Double)।

Separate Chaining

ধারণা: table-এর প্রতিটি ঘর একটি linked list (chain)-এর মাথা। একই index পাওয়া সব key ওই chain-এ জমা হয়।
Insert: index বের করো → chain-এর শেষে (বা মাথায়) যোগ করো — O(1)।
Search: index বের করো → chain ধরে সরলরেখায় খোঁজো।
Delete: chain থেকে node সরাও।

উদাহরণ: hash = key mod 5, keys = 12, 15, 22, 25, 37 (নিচের chain নিচের দিকে বাড়ছে):

Performance: m = ঘর, n = key, α = n/m। simple uniform hashing ধরলে Search ও Delete গড়ে O(1 + α), Insert O(1)। α = O(1) হলে সবই O(1)। Worst case chain লম্বা হলে O(n)।

Open Addressing

ধারণা: সব key table-এর ভেতরেই থাকে, কোনো বাইরের list নেই (closed hashing-ও বলে)। তাই সবসময় n ≤ m, অর্থাৎ α ≤ 1। Collision হলে একটি probe sequence ধরে পরের ঘর দেখা হয়।
Insert(k): probe করতে থাকো যতক্ষণ খালি ঘর না মেলে, তারপর বসাও।
Search(k): probe করতে থাকো যতক্ষণ k না মেলে বা খালি ঘর (empty) না আসে — empty এলে k নেই।
Delete(k): ঘর সরাসরি খালি করলে পরের key-র search ভেঙে যায় (সমস্যা ৫)। তাই ঘরে “deleted” (tombstone) চিহ্ন দেওয়া হয়। Insert ওই ঘর ব্যবহার করতে পারে, কিন্তু Search deleted ঘরে থামে না।

অ্যানিমেশন ল্যাব — ধাপে ধাপে

কীভাবে চালাবে: পদ্ধতি, table size (m) ও key বেছে নাও (key কমা দিয়ে লেখো)। ▶ চাপলে প্রতিটি key নিজের index-এ উড়ে যাবে; ঘর ভরা থাকলে লাল হবে ও পরের probe-এর হিসাব দেখাবে। “⏭ এক ধাপ” দিয়ে নিজের গতিতে এগোও। Preset-এ পাঠ্য উদাহরণগুলো আছে। Double hashing-এ p = m − 2।

Hashing-এর ব্যবহার (Applications)

১) Data integrity ও security:
• Password storage — plain text নয়, অপরিবর্তনীয় “fingerprint” (hash) রাখা হয়।
• File comparison / Message digest — hash মিলিয়ে file নষ্ট বা বদলানো ধরা যায়।
• Blockchain — প্রতিটি block আগের block-এর hash ধরে থাকে, তাই কিছু বদলালে chain ভেঙে যায়।
• Fraud / malware detection — পরিচিত hash-এর database-এর সাথে মেলানো।
২) Database ও search:
• Database indexing — hash দিয়ে সরাসরি record-এ পৌঁছানো।
• Distinct element ও frequency counting — hash value-কে key ধরে গোনা।
• Dictionary / Associative array — Python dict, C++ unordered_map, Java HashMap।
• Rabin-Karp — string search-এ text-এর অংশের hash মিলিয়ে দ্রুত অমিল বাদ দেওয়া।
৩) Network ও system:
• Load balancing — consistent hashing দিয়ে request সমানভাবে server-এ ভাগ করা।
• Bloom filter — অল্প memory-তে “আছে কি না” পরীক্ষা (ছোট ভুলের সম্ভাবনাসহ)।
• Network routing ও Caching — hash-ভিত্তিক key দিয়ে দ্রুত lookup।
৪) বিশেষ কাজ:
• Image processing — perceptual hashing দিয়ে duplicate/similar ছবি ধরা।
• Symbol table — compiler-এ identifier-কে memory location-এর সাথে map করা।
• Graphics grid — 3D object-কে spatial grid-এ hash করে সাজানো।

Hash Table বনাম BST

Hash table-এ search/insert/delete গড়ে O(1), আর self-balancing BST-তে (AVL, Red-Black…) O(log n)। তবুও BST কেন লাগে?

BST-র সুবিধা: (১) Inorder traversal-এ সব key sorted পাওয়া যায়। (২) Order statistics (k-তম ছোট), floor/ceil (কাছের ছোট/বড়) ও range query সহজ। (৩) সব operation-এ worst case O(log n) গ্যারান্টি; hash-এ O(1) শুধু গড়ে, resize-এর সময় O(n)। (৪) BST-তে n key-তে ঠিক n node, hash table বড় রাখতে হয় বলে memory বেশি লাগে। (৫) নিজে বানানো সহজ; hashing-এ সাধারণত library ভরসা।

C++ কোড অ্যানিমেশনে: isSubset()

সমস্যা: a[] ও b[] (element distinct)। b[] কি a[]-এর subset? ধারণা: a[]-এর সব element একটি set-এ রাখো, তারপর b[]-এর প্রতিটি element set-এ খোঁজো; পেলে একটি মুছে দাও, না পেলে সাথে সাথে false। নিচে কোডের প্রতিটি লাইন চলার সাথে set-এর অবস্থা দেখো।

⚠ একটি জরুরি তথ্য: এই কোডের multiset আসলে hash table নয় — এটি Red-Black tree (sorted), তাই find/erase O(log m) এবং মোট সময় O((m+n) log m)। সত্যিকারের hashing পেতে unordered_multiset (বা distinct হলে unordered_set) লাগে, তখন গড়ে O(m+n)। নিচের অ্যানিমেশনে container বদলে দুটোই দেখতে পারবে। (এই কোডে <vector> ও <set> include নেই; নিজের কম্পাইলারে চালালে যোগ করে নিও।)
পুরো কোড (main সহ)
#include <iostream>
#include <vector>
#include <set>
using namespace std;

bool isSubset(vector<int>& a, vector<int>& b) {

    // Create a hash set and insert all elements of a
    multiset<int> hashSet(a.begin(), a.end());

    // Check each element of b in the hash set
    for (int num : b) {
        if (hashSet.find(num) == hashSet.end()) {
            return false;
        }
        hashSet.erase(hashSet.find(num));
    }

    // If all elements of b are found in the hash set
    return true;
}

int main() {
    vector<int> a = {11, 1, 13, 21, 3, 7};
    vector<int> b = {11, 3, 7, 1};

    if (isSubset(a, b)) {
        cout << "true" << endl;
    } else {
        cout << "false" << endl;
    }

    return 0;
}
Output: true — কারণ 11, 3, 7, 1 সবই a[]-তে আছে।

C++-এ Hashing কীভাবে implement হয়

STL-এ hash-ভিত্তিক container: unordered_set (শুধু key), unordered_map (key–value), unordered_multiset / unordered_multimap (duplicate সহ)। ভেতরে থাকে bucket-এর array, প্রতিটি bucket একটি chain (linked list) — অর্থাৎ separate chaining। index = hash(key) mod bucket_count। load factor সীমা (ডিফল্ট max_load_factor = 1.0) পার হলে bucket সংখ্যা বাড়িয়ে rehash হয়।

বিপরীতে set / map / multiset হলো balanced tree — sorted, কিন্তু O(log n)।

unordered_set<int> s = {11, 1, 13, 21, 3, 7};
cout << s.bucket_count();   // bucket সংখ্যা (m)

নিজে বানানো (separate chaining) — অ্যানিমেশনের “unordered_multiset” মোডের সমতুল্য:

#include <vector>
#include <list>
#include <algorithm>
using namespace std;

struct HashSet {
    vector<list<int>> t;                 // bucket-এর array
    HashSet(int m = 7) : t(m) {}
    int h(int k) { return k % t.size(); }   // division method

    void insert(int k) { t[h(k)].push_back(k); }

    bool eraseOne(int k) {                  // find + erase একসাথে
        auto& c = t[h(k)];
        auto it = find(c.begin(), c.end(), k);
        if (it == c.end()) return false;
        c.erase(it);                        // শুধু একটি k মোছে
        return true;
    }
};

bool isSubset(vector<int>& a, vector<int>& b) {
    HashSet s;
    for (int x : a) s.insert(x);            // O(m)
    for (int x : b)
        if (!s.eraseOne(x)) return false;   // গড়ে O(1) করে, মোট O(n)
    return true;
}
মনে রাখো: hash(k) = k mod m → index → ওই bucket-এর chain-এ খোঁজা। chain ছোট থাকলে (α ছোট) সব operation গড়ে O(1)। STL-এ bucket সংখ্যা সাধারণত prime রাখা হয় এবং rehash নিজে নিজেই হয়।
