Time Complexity কী?

একটি algorithm চালাতে processor-কে কতগুলো মৌলিক operation করতে হয়, তার হিসাবই time complexity। যে algorithm-এর operation কম, সে বেশি দ্রুত (faster)। ঘড়ির সেকেন্ডে সময় মাপলে কম্পিউটারভেদে ফল বদলায়, তাই আমরা operation গুনি।

গোনার নিয়ম: Assignment (=) → ১; Arithmetic (+ − * /) → ১; Comparison (> < ==) → ১; return → ১। Algorithm-এর মোট operation = সব আলাদা operation-এর যোগফল।
উদাহরণ ১: int function1(int x){ x = x + 1; return x * 5; }
x+1 → ১ (যোগ) + ১ (assign) = ২; x*5 → ১ + return ১ = ২; মোট 4 operation।
উদাহরণ ২ (loop): 
int sum = 0;                 // 1
for(int i=1; i<=n; i++)      // i=1 → 1;  i<=n → n+1 বার;  i++ → n বার
    sum = sum + i;           // 2n   (যোগ + assign)
return sum;                  // 1
T(n) = 1 + 1 + (n+1) + n + 2n + 1 = 4n + 4
n=1 হলে 8 operation (হাতের নোটের “Total time: 8”)। Loop-এর ভেতরের কাজ যত বার চলে, খরচও তত বার যোগ হয়।

তুলনা: Linear search কত operation খায়?

int linearsearch(int A[], int n, int value){
  for(i=0; i<n; i++)          // 1 + (n+1) + n
     if(A[i]==value)          // n বার তুলনা
         return i;            // সফল হলে
  return -1; }                // 1

সবচেয়ে খারাপ ক্ষেত্রে (value নেই বা শেষে): T(n) = 1 + (n+1) + n + n + 1 = 3n + 3। অর্থাৎ n=10 হলে 33 operation, n=100 হলে 303, n বাড়লে operation ও সমানুপাতে বাড়ে।

Input size-এর ওপর নির্ভর করে না এমন: int fun(int a,int b){ x=a*b; return x; } → T(n) = 2 + 1 = 3 সবসময় (constant)। Input যত বড়ই হোক সময় একই।
Best/Worst case: একই algorithm-এ input-এর ধরনভেদে সময় আলাদা হয়। যদি time complexity সবচেয়ে বেশি হতে পারে এমন input ধরি, সেটিই Worst case time complexity। সাধারণত worst case-ই বিশ্লেষণ করা হয়, কারণ এটি “এর বেশি সময় কখনোই লাগবে না” এই নিশ্চয়তা দেয়।

Time Complexity দিয়ে algorithm তুলনা

ধরা যাক দুটি algorithm: T₁(n) = n² এবং T₂(n) = 215·n। ছোট n-এ T₁ কম, কিন্তু n বাড়লে T₁ অনেক দ্রুত বাড়ে।

n = 215 পর্যন্ত n² ≤ 215n; n=215-এ দুটি সমান (46225); তার পর থেকে n² সবসময় বেশি। সিদ্ধান্ত: input বড় হলে T₂ (linear) জেতে — তাই আমরা “n বড় হলে কে কেমন” তা দেখি। এই বড় n-এর আচরণই asymptotic বিশ্লেষণ।

শুধু সবচেয়ে বড় term রাখি

T₁(n) = 67n² + 58n + 35, ধরা যাক n = 10⁷। তখন 67n² ≈ 67×10¹⁴ আর 58n ≈ 58×10⁷; দ্বিতীয় অংশ প্রথমটির তুলনায় এত ছোট যে ধরার দরকার নেই। তাই T₁(n) = O(n²) (শুধু বড় term, constant বাদ)। একইভাবে T₂(n) = 55n² + 10√n + 3 = O(n²)।

নিচের সবগুলো O(n²): 7n²+2n+37, n²+√n, 75n²। নিচের সবগুলো O(n): 6n+39, 6n+log n+39, 85n।
বৃদ্ধির ক্রম (ছোট→বড়): 1 < log n < √n < n < n log n < n² < 2ⁿ < n!

Big-O অ্যারিথমেটিক ও loop বিশ্লেষণ

যোগ নিয়ম: O(f(n)) + O(g(n)) = O(সবচেয়ে বড়টি)। গুণ নিয়ম: O(f(n)) × O(g(n)) = O(f(n)·g(n))।
int n = 5;                       // O(1)
int sum = 0;                     // O(1)
for(int i=1; i<=n; i++) sum += i;    // O(n)
for(i=1; i<=n; i++)              // O(n)
   for(j=1; j<=n; j++) ;          // × O(n)  ⇒ O(n²)
মোট = O(1)+O(1)+O(n)+O(n²) = O(n²)

for(int i=1; i<=n; i++)          // O(n)
   for(j=1; j<=n; j=j*2) ;       // × O(log n)  ⇒ O(n log n)

Worst, Average ও Best case

Worst case: সবচেয়ে বেশি সময় (upper bound)। Linear search-এ element শেষে বা নেই ⇒ n তুলনা ⇒ Θ(n)।
Best case: সবচেয়ে কম সময় (lower bound)। element প্রথম ঘরে ⇒ ১ তুলনা ⇒ Θ(1)।
Average case: সম্ভাব্য সব ইনপুটের সময়ের গড়। Element i-তম ঘরে থাকলে i তুলনা:

গড় = (1+2+…+n)/n = [n(n+1)/2]/n = (n+1)/2 ⇒ Θ(n)
বাস্তবে প্রায় সবসময় worst case বিশ্লেষণ করা হয় (নিশ্চয়তা দেয়)। Average case কঠিন — সব ইনপুটের বণ্টন জানতে হয়। Best case-এর মূল্য কম, কারণ worst case-এ algorithm অনেক খারাপ চলতে পারে।

Asymptotic Notation: O, Ω, Θ

Big-O (upper bound): f(n) = O(g(n)) যদি ধনাত্মক c ও n₀ থাকে যাতে 0 ≤ f(n) ≤ c·g(n) সব n ≥ n₀-এর জন্য।
Big-Ω (lower bound): f(n) = Ω(g(n)) যদি 0 ≤ c·g(n) ≤ f(n) সব n ≥ n₀।
Θ (tight bound): f(n) = Θ(g(n)) যদি c₁·g(n) ≤ f(n) ≤ c₂·g(n), অর্থাৎ O ও Ω দুটিই সত্য।
উদাহরণ (Big-O): f(n) = 4n³+10n²+5n+8, g(n) = n³। n ≥ 1-এর জন্য f(n) ≤ (4+10+5+8)n³ = 27n³ ⇒ c=27, n₀=1 দিয়ে প্রমাণিত, f(n) = O(n³)। (বইয়ে c=5, n≥4 লেখা আছে — এটি ঠিক নয়: n=4-এ f=444 > 5×64=320। c=5-এর জন্য n₀=11 লাগে।)
উদাহরণ (Big-Ω): f(n)=3n+2, g(n)=n। c=3 নিলে 3n ≤ 3n+2 সব n-এ সত্য ⇒ f(n) = Ω(n)। আবার 3n+2 ≤ 4n (n≥2) ⇒ O(n) ⇒ Θ(n)।

প্রশ্ন: কোন loop সবচেয়ে efficient?

চারটি function; সবগুলোতে একটি for loop ও ভেতরে একই কাজ। n ধনাত্মক input size।

Loopকত বার চলেComplexity
A: for(i=0;i<n;i++)n বারO(n)
B: for(i=0;i<n;i+=2)n/2 বার (constant বাদ)O(n)
C: for(i=1;i<n;i*=2)i = 1,2,4,…,2ᵏ; 2ᵏ=n ⇒ k = log₂nO(log n)
D: for(i=n;i>−1;i/=2)i কখনো −1-এর নিচে যায় না (শেষে 0/2=0), condition সবসময় সত্য ⇒ থামে নাঅসীম
উত্তর: C। log n < n/2 ≈ n তাই C সবচেয়ে দ্রুত; D তো শেষই হয় না।
